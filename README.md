# 星铁游戏搭子 0.8.2

这是面向 N.E.K.O 的《崩坏：星穹铁道》陪玩插件。它提供自动画面观察、视觉建档、知识查询、玩家语境、基础分析、纠错记忆、经历记录和事件上下文，不修改 N.E.K.O 本体，也不修改或操作游戏客户端。

## 最快使用

1. 打开插件面板。插件会自动在插件外部准备带版本和哈希校验的资料组件；失败时仍保留最小角色防幻觉名单。
2. 点击“开始自动观察”并切回游戏。画面稳定后，插件先判断是否属于受支持页面，再读取该页面的限定区域；N.E.K.O. 会收到“最新一帧视觉上下文 + 数据库约束过的结构化事实”，排队中的旧画面会被新画面覆盖。
3. 直接聊星铁，或在需要时上传角色列表截图。星铁事实、角色身份、档案、队伍和培养问题会先走统一查询入口。
4. 截图识别结果必须经过固定版本角色注册表校验，并先进入待确认区；玩家确认后才写入正式档案。
5. 如果认错或语音同音字错了，在面板告诉插件“错成什么、实际是谁”。未知别名可以长期保存；两个真实角色之间只记录为待确认歧义，绝不会把一个角色全局改写成另一个。

原始截图只用于本次视觉识别，不写入插件存储。手动角色输入仅作为纠错兜底。

## 当前包含

- 插件主动维护的星铁陪玩会话和可信上下文；
- 事件分级主动陪伴：战斗、跃迁、结算、队伍准备和数据库确认角色会请求简短回应；剧情与普通菜单只静默同步；
- 探索状态持续空闲约两分半后可触发一次低优先级闲聊，并受全局节奏与场景冷却约束；
- 统一的 `hsr_companion_prepare` 查询入口，优先使用插件事实；
- 前台星铁窗口自动观察、画面变化去重和隐私暂停；
- 最新游戏帧以只读上下文送给 N.E.K.O.，沿用成熟游戏插件的“限频、合并、只保留最新帧”策略；
- 游戏画面 → 共享 RapidOCR → 页面分类 → 限定区域识别 → 多帧稳定 → 事件裁决；
- 角色截图 → 受支持页面 → 角色名区域 → 数据库实体 ID → 玩家确认；
- 截图、语音和聊天纠错记忆；
- 88 名角色身份的离线严格注册表，固定到可审计的上游提交；
- 外部 SQLite 资料组件：角色形态、技能、星魂、行迹、培养、光锥效果、遗器套装、物品、命途和属性；
- 插件包内只保留约 8KB 的角色身份白名单；
- 可更正、可清除的玩家结构化档案；
- 可解释的基础队伍规则分析；
- 插件内游戏经历记录；
- 带去重和过期判断的游戏事件入口；
- 截图结果暂存、确认与放弃工具；
- 一站式 Hosted UI 面板。
- 当前画面状态识别：剧情、战斗、探索、菜单、队伍准备、跃迁、结算、加载、其他或未知。

## 重要限制

- 外部资料组件固定到明确的上游提交，不代表自动包含之后的游戏版本；面板会显示当前状态。
- 角色注册表只做精确名称/别名匹配，不使用模糊猜测；未知名字不能进入正式档案，也不会因为读音相近就被断言为“不存在”。
- 0.8 首版可靠角色识别复用 N.E.K.O. 共享 RapidOCR，只在受支持页面和限定区域返回实体 ID。最新画面会同时供 N.E.K.O. 理解场景，但没有清晰角色名时不得把模型的外观猜测升级为数据库事实；自由视角头像级识别仍需要后续独立视觉资源包。
- 角色注册表来自 `Mar-7th/StarRailRes` 固定提交，采用 AGPL-3.0-only；来源、变更和许可链接见 `THIRD_PARTY_NOTICES.md`。游戏 IP 权利仍归原权利人所有。
- 自动观察仅在目标游戏窗口位于前台时工作，切换应用或最小化游戏会暂停；原始画面不落盘。
- 画面状态在五分钟后自动视为过期；模型自报状态永远不能覆盖插件验证状态。
- 当前不包含完整账号同步、自动操作或复杂战斗模拟。
- 主动陪伴默认随自动观察启用，可在面板一键静音；静音不会关闭识别和状态同步。
- 玩家档案和经历保存在插件存储中，不等同于 N.E.K.O 长期记忆。

外部资料组件可由 `scripts/build_data_pack.py` 从固定提交重建。请先阅读 `ARCHITECTURE.md` 与 `THIRD_PARTY_NOTICES.md`。
