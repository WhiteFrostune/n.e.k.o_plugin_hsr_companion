## 改动与稳定判定

- `__init__.py` 仅在原观察循环接入调度和 full 提交后的源帧锚定；原取证、核验、缓存、交付路径不替换。
- L2a `detectors/patrol_regions.py` 选择可覆盖完整内容的监视区域；L2b `runtime/patrol.py` 决定是否还需要 full，已登记 layers.toml。白名单仍为零，没有新增依赖例外。
- 仅已有可信完整来源、原生页面控件、逐字段证据的角色/遗器详情页可进入静态调度。不熟悉的页面/布局、缺证据、捕获异常、待确认对象等沿用原扫描调度，不宣称所有页面都优化。
- 锚定**实际提交 full 的那张源帧**。之后至少两张不同序号、不同采样时间、采样年龄不超过原 2 秒的帧，其页面控件、名称、全部已知证明、完整信息面板像素须一致。不是整图 hash，也不是只看标题。
- 完整信息面板包括未识别的数值行；原生 RGB 像素做摘要，不缩略，避免缩小后丢一位数字。模型中央装饰动画可忽略；任何已知证据落在中央仍覆盖，数值区向左延伸也随证据扩展。
- 信息区有变化时恢复 full；锚点受质疑后不逐帧滚动到新图，必须等待新的 full 提交。换 PID、epoch、捕获失败代次、full 提交序号也不能沿用旧锚。
- 手动刷新、尚未完成的场景/身份确认及补答仍有需求；正在按需区域读的问题，不再额外制造一轮冗余 full。连续采集及原 watch_latest_frame 未关闭。
- 不向调度摘要赋予任何回答资格；不写事实、回执或 observed_at。15/60 秒保鲜期、输入新帧 ≤2 秒、DIRECT_WAIT_SECONDS=8、姓名匹配/复核门槛均未改动。

## 重放方法及边界

脚本 `scripts/replay_static_patrol.py` 使用真实本地 OCR 后端、常驻观察循环及公开 hsr_companion_prepare 入口；新旧顺序在第二轮反转。bb1838d 的原观察函数由 git show/AST 提取运行，其余生产调用路径与当前保持一致；不把孤立 OCR 时间当完整工具时间。

SDK 存储为内存替身，禁止真实消息和 USER_CONTEXT_GET。已保存的真珠详情页为真实目标截图；切页前是合成遗器页（真实 OCR 读取，没有替换 OCR 输出），不是实机连续录像。两张预制帧在中央装饰区域交替一个小色块，确保整图摘要持续变化。游戏/助手/宿主 RPC 与模型转述并未实测。

正式成功必须同时满足：整个工具返回 ≤8 秒、identity allowed、当前视觉结果含目标身份、query state=ready。仅快速返回 unconfirmed 不算通过。

补清测量前提后，脚本记录第一提交时的待确认状态、初始化完成时间；先等原身份/场景确认自然完成、生产者空闲，再开始十秒稳定窗口。未降低确认次数，未修改 8 秒产品期限。真实角色页该初始化约 55–61 秒，单列而不藏入“稳定页已达标”；这是 A 仍需处理的剩余边界。
