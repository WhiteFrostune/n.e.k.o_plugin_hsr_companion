# A：提问优先与请求核验期限

父版本为 D 的 `f1d596b`。本轮使用单个 OCR 后端。重放读取保存的角色详情帧和 D 已有的合成换页源，SDK 使用内存替身。当前安装、视觉助手和游戏均未参与。

D 在区域读取登记后才允许正在运行的 full 让位。已有检查点包括场景探针、原生图块、补读和姓名复核之间，以及整体 OCR 结束与最终核验之间。后端调用已经开始时需要等它返回。D 的后台检查点也会先尝试消费排队的核验。

A 在初始缓存尝试前登记可独立区域读取的角色身份提问。后台的下一个检查点先检查让位再消费队列。后台占着 OCR 时，初始缓存保留像素验证命中，文字需要复核时优先读当前区域。区域读取从工作者获得使用权后才取帧，随后执行原页面、姓名、证据审核。纯属性跨页和确实需要 full 的请求保留原交接探测。后台因让位退出后仍按原巡逻逻辑重试未完成的确认。

普通查询的核验绑定原工具查询期限。补答的核验绑定原待办对象及它已登记的到期时间。工作前、取帧后、提交结果前检查期限和原快照边界。短等待片耗尽不撤销仍有效的核验。后台依旧执行像素和对象保护，范围不同的核验不能借用对方的回执。现有原生调用退出前，调度器保留工作者，避免同时推理。

后台场景探针和宽图块沿超过 680 像素的轴拆成两个带重叠裁剪；低分辨率场景探针的高度轴单独以 420 为界。裁剪采用输入已有的像素比例并恢复全局坐标；标题探针结果在两块齐全后才合成。同一 v5 后端只对这些裁剪和高分辨率角色区域首读减少检测器的额外上采样（最短边默认 736，普通裁剪 512，场景预览和 1440p 以上的角色首读裁剪 320），原始裁剪像素、检测得分门槛和姓名独立复核保留。配置在单次调用结束后恢复；共享后端兼容路径保留原参数和原分块。增加调用次数可能提高完整扫描成本，也可能让原扫描预算内完成的区域数变化。需要结合以下重放数据与保护用例判断。

8 秒期限、姓名确认次数与门槛、15/60 秒保鲜边界、2 秒新帧要求和 `observed_at` 取值沿用原实现。

## 离线重放
